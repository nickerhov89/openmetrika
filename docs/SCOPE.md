# OpenMetrika: функциональный контракт

Самостоятельная система веб-аналитики по образцу рабочих сценариев Яндекс Метрики.
Оригинальный код и интерфейс; MIT. Это не исходники и не официальный продукт Яндекса.

## Результат, который нужно проверить

1. Установка из исходников и Docker, первый администратор, вход, несколько счётчиков,
   права на счётчик, настройка разрешённых доменов, доступ к API и экспорт.
2. Встраиваемый счётчик: просмотры, SPA-переходы, события, UTM, внешние ссылки,
   скачивания, цели, активное время, глубина скролла, ecommerce.
3. Сводка, динамика, сравнение периодов, источники/кампании, страницы входа/выхода,
   устройства/браузеры/ОС, посетители, сегменты и сохранённые отчёты.
4. Цели и конверсии, последовательные воронки, выручка/заказы/товары.
5. Карты кликов/ссылок/скролла и аналитика форм на фактически собранных событиях.
6. Запись и воспроизведение сессий на rrweb, маскирование ввода, переключение страниц,
   поиск визитов, удаление записей и срок хранения.
7. API, CSV, резервная копия/восстановление, документация по установке, безопасности,
   интеграции счётчика, воспроизводимое демо и проверка сквозного сбора данных.
8. Упаковка open-source: MIT, README RU/EN, CONTRIBUTING, SECURITY, CI,
   Docker Compose, релизный архив и публичный GitHub-репозиторий.

Готовность подтверждается работающими сценариями, не наличием пунктов меню.

## Принципиальные границы

Данные закрытой рекламной экосистемы Яндекса (Директ, пол/возраст/интересы,
поисковые запросы, скрытые поисковиком, межсайтовая идентичность) не могут
возникнуть из независимого счётчика. Их нельзя подменять выдуманными данными.
Географию показывать только при наличии явного источника GeoIP.
Для сквозной аналитики нужны реальные внешние импорты расходов и CRM-доходов.
Соответствующие ограничения и поддержанные импорты должны быть документированы.

## Дополнения v0.2

Выбор основной цели, сегменты И/ИЛИ с параметрами событий, редактируемые
межвизитные воронки и переход к потерянным визитам; часовой пояс счётчика и
сравнение периодов; серверный импорт стадий CRM, оплаты/возвраты/прямые
затраты, экономика каналов и когорты. История привязывается через ClientID
или ID визита. Автоматическое подключение аккаунта amoCRM/Директа, склейка
устройств и полноценный прогноз LTV в этот релиз не входят.
